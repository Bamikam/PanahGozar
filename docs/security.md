# Security model

This document describes the controls implemented in the repository, the trust boundaries, and
the residual risks operators must manage. It is not a claim of complete security or compliance.

## Trust boundaries

- **Browser session:** untrusted input. All payloads are validated and React escapes rendered
  values. Strict CSP reduces script injection impact.
- **Administrators/operators/viewers:** authenticated staff. Roles are enforced server-side;
  UI hiding is not a security control.
- **Imported configuration text:** untrusted. Xray/sing-box JSON is parsed with size/depth
  limits and schema checks; OpenVPN profiles reject executable directives. Embedded credentials
  are not imported into the panel's credential store.
- **External protocol servers:** outside this application. The panel does not connect to them,
  verify them, or execute commands on them. Exported files are data and must be applied by an
  operator.
- **PostgreSQL:** trusted persistence with least-privilege credentials. It stores sealed
  credentials, session hashes, subscription hashes, and audit events.

## Authentication and sessions

- Passwords hashed with Argon2id (`@node-rs/argon2`, 19 MiB, t=2, p=1).
- Login timing is equalized for unknown/inactive users with a dummy Argon2 verify.
- Login rate limited to 8 attempts / 5 minutes per client IP.
- Session token: 32 random bytes, base64url, only SHA-256 hash stored. Cookie is HttpOnly,
  SameSite=Strict, Secure when `PUBLIC_URL` is HTTPS (or `COOKIE_SECURE=true`).
- New login revokes all sessions for that user and issues a fresh token.
- Password changes, role changes and deactivation revoke sessions.
- Sessions expire after 24 hours; idle sessions are extended after activity.
- CSRF double-submit: a random `pg_csrf` token, JS-readable, must match the server-side session
  token in `x-csrf-token` for every authenticated mutation.
- `SameSite=Strict` and same-origin CORS behavior further reduce cross-site request risk.
- This release does not implement MFA, SSO, WebAuthn, or source-IP session binding.

## Authorization

Roles:

- `admin`: full control, user administration, audit log, deletes.
- `operator`: manage clients/configurations/subscriptions, export artifacts, diagnostics.
- `viewer`: read-only access to clients/configurations/protocols/settings/diagnostics.

The global API hook requires a session for every matched `/api` route except an explicit
public allowlist (`health`, `ready`, `setup/status`, `setup`, `auth/login`, subscription fetch,
OpenAPI/docs). Role checks are performed at each sensitive route and mirrored in the UI.
Unknown API paths return 404 without probing access.

Last-admin protection prevents demoting/deactivating/deleting the final active administrator.

## Secrets and cryptography

- Credentials and WireGuard server keys are sealed with AES-256-GCM using Node's standard
  crypto: random 96-bit IV, authentication tag, versioned envelope.
- Only sealed values are stored in PostgreSQL. Raw values are opened only in-process for a
  specific authorized export or subscription generation.
- List/detail APIs return only non-secret display metadata. There is no endpoint that dumps
  all plaintext credentials.
- Private keys, passwords, tokens, URLs, cookies, UUIDs and credential objects are redacted
  from Pino logs. Request URL logging hides the entire URL; subscription bearer tokens cannot
  appear in access logs.
- Subscription tokens are 160-bit CSPRNG values, SHA-256-hashed at rest, displayed once at
  creation/rotation, `no-store`, revocable, expiring and rotatable.
- `ENCRYPTION_KEY` must be 32 bytes (hex or base64). Loss makes sealed data unrecoverable.
  Rotation is not automated.
- No custom cryptographic primitives are implemented.

## Input handling

- Zod schemas bound every protocol's config, hosts, ports, paths, tunnel settings and file
  paths. UUIDs, WG keys, MTProto secrets and SI/SPKI serialization are validated.
- JSON imports limited to 1 MiB and 32 levels.
- No user-controlled value is passed to a shell. There is no dashboard shell endpoint.
- SQL is generated by Prisma. Raw queries are static `SELECT`s for health checks.
- CSV/HTML injection is handled by rendering escaped text, not `dangerouslySetInnerHTML`.
- Imported OpenVPN profiles are static-parsed; directives that can execute programs or open
  management interfaces are rejected.
- Outbound network requests are not performed by the app, so SSRF surfaces (URL fetch,
  webhooks, external health probes) are intentionally absent.

## Headers, errors and transport

- Helmet: CSP (`default-src 'self'`), HSTS when public URL is HTTPS, `X-Frame-Options: DENY`,
  `X-Content-Type-Options: nosniff`, referrer policy no-referrer, no object embedding.
- CORS is not opened to arbitrary origins; the SPA is same-origin.
- 5xx responses are sanitized to `{ "error": "internal server error" }`; stack traces and
  database details are logged server-side only.
- Rate limits: global 300/min, login 8/5 min, setup 5/15 min, password 5/15 min, public
  subscription 60/5 min. In-memory store is appropriate for one replica.
- `TRUST_PROXY=true` trusts platform forwarding headers. Do not expose the app directly to the
  internet without a trusted proxy, or client IP-based rate limiting can be spoofed.

## Database

- All state in PostgreSQL; no container-local source of truth.
- Foreign keys and indexes in Prisma migrations; soft deletion for clients/configurations.
- Session/permission changes propagate immediately because sessions are validated per request.
- Application database credentials should be least-privilege DML plus migration rights, not
  superuser. Managed PostgreSQL network access should be restricted to the service.
- Provider encryption at rest and backups are the operator's responsibility.

## Deployment controls

- Non-root Docker user; no privileged mode, host networking, capabilities, kernel modules,
  arbitrary UDP listeners, or background protocol daemons.
- Single replica assumption for in-memory rate limiting. Scaling requires shared state.
- Startup environment validation fails closed without echoing values.
- Health/readiness endpoints expose status and reasons but no secrets.
- Graceful SIGTERM/SIGINT with a bounded shutdown.
- CI runs `pnpm audit --prod --audit-level=high`; the production dependency set currently has
  no known vulnerabilities. Development-only build tooling is audited separately and is not
  shipped in the server or browser runtime.

## Residual risks and non-goals

- No runtime enforcement of traffic quotas, connection limits, or network-level expiry. The UI
  explicitly states which limits are panel-delivery-only.
- No live health verification of external protocol servers; `running_verified` is unreachable
  by design in this deployment.
- OpenVPN client profiles may embed certificate/private-key material as part of the imported
  profile. They are exposed only through authenticated operator/admin routes, but at-rest
  protection depends on PostgreSQL/provider encryption and database access controls.
- No built-in MFA, audit log export/WORM, SIEM integration, or credential key rotation tooling.
- No per-tenant isolation; the panel is a single administrative domain.
- Rate limiting is per-process; restart clears counters.
- UI admin users can still inspect configuration material allowed by their role. Treat
  administrator accounts as highly privileged.
- `SETUP_TOKEN` remains valid only while no administrator exists; remove it after provisioning.

## Hardening checklist

- [ ] `SESSION_SECRET` and `ENCRYPTION_KEY` generated by CSPRNG, stored in the platform secret
      manager, backed up appropriately.
- [ ] `PUBLIC_URL` set to the exact HTTPS origin; secure cookies confirmed.
- [ ] `SETUP_TOKEN` removed after the first administrator.
- [ ] Managed PostgreSQL private networking, least-privilege user, backups enabled.
- [ ] Platform access to the Railway/Render project restricted; audit platform activity.
- [ ] One replica with in-memory rate limiting.
- [ ] Regular dependency audits (`pnpm audit`) and base-image updates.
- [ ] Exported server artifacts applied only on trusted external hosts.
- [ ] Platform logs retained and monitored; no secret values logged by this app.
- [ ] Verify `/api/ready` and a real login after every deploy.
